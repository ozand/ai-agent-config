# Reference audit CLI

`python scripts/reference_audit.py --root PATH [--root PATH ...] [--format json|table|mermaid|all] FILE...`

Supply every input file explicitly and declare each containing root. The CLI is offline and read-only: it does not execute content, expand environment variables, crawl directories, make network requests, or read target contents while resolving references. Inputs must be UTF-8 and no larger than 1,000,000 bytes; paths may be at most eight components beneath a declared root. The CLI emits at most 10,000 reference records total across all supplied inputs; exceeding this bound fails the audit without a partial report. File opening uses root-relative no-follow handles on supported POSIX platforms and validates the final path of the opened handle on Windows; it fails closed on platforms without the required primitives. This rejects symlink traversal and rechecks containment on the opened handle; it does not guarantee the opened in-root file is the same inode observed during initial path validation, or defend against a privileged actor replacing the declared root itself. Default format is `all`; JSON is the canonical versioned report and table/Mermaid are projections. Output is stdout only.

Extraction is deliberately conservative and incomplete: Markdown links, selected frontmatter path-like values, and literal path-like text become evidence records. Dynamic targets and ambiguous names remain unresolved. Exact path, entity match, binding, relation, requirement strength, and bounded `search_scope` are separate fields. Each record states that exact-path checks use declared roots while entity correspondence uses only supplied-input basenames; scope identifiers/counts do not reveal root paths. Unchecked and unresolved results remain bounded to those searches, not the host or global environment; a mention is not proof of installation, activation, permission, or semantic identity. Absolute paths and likely credentials are redacted. The JSON report includes an opaque source-ID-to-root-relative-path registry for traceability; path components matching known sensitive patterns are redacted, and declared root paths are never emitted. Fragment-only destinations and directory destinations remain unchecked because v1 does not validate anchors or directory indexes. Requirement strength is `unknown` in v1 unless future extraction logic can establish a scoped qualifier safely. Reports must be reviewed before sharing; sanitization is best-effort, not a guarantee against every sensitive value. URI schemes are classified as external without dereferencing or network access; `file:` URIs are redacted and never followed.
